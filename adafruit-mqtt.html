IoT Learning — Assignment 02

Adafruit IO MQTT

Building an IoT cloud-control system using an ESP32, MQTT communication, Adafruit IO and a remotely controlled bulb.

01

Overview

This assignment focused on understanding how an IoT device can communicate with a cloud platform using the MQTT protocol. I used an ESP32 as the IoT device and Adafruit IO as the cloud platform for sending and receiving control data.


The main practical objective was to control a connected bulb remotely through an Adafruit IO dashboard. The dashboard sends the required control value through MQTT, which is received by the ESP32 and used to control the physical output.


This helped me understand the complete communication path from the cloud dashboard to the microcontroller and finally to the physical output.

02

Concepts

MQTT

MQTT is a lightweight messaging protocol commonly used in IoT systems. It allows devices and applications to exchange small messages efficiently.

Publisher

A publisher sends a message to an MQTT communication channel. In this system, the cloud dashboard can publish a control value.

Subscriber

A subscriber listens for messages from the required communication channel. The ESP32 receives the control information and responds accordingly.

Broker

The MQTT broker manages communication between publishers and subscribers. Adafruit IO provides the cloud-side MQTT infrastructure used in this assignment.

Wiring / Setup

I first prepared the ESP32 and the output-control circuit. The ESP32 was connected to the required output device so that a control signal from the microcontroller could change the physical output state.


After completing the hardware connection, I connected the ESP32 to Wi-Fi and prepared the software environment in Arduino IDE.


The Adafruit IO account and dashboard were then configured so that the ESP32 could exchange control information with the cloud platform through MQTT.

The exact GPIO/pin numbers are intentionally not stated here because the supplied evidence does not identify the final pin mapping.
06

Implementation

I implemented the system in stages rather than testing the entire setup at once.


  1. Prepared the ESP32 hardware and output circuit.
  2. Installed and opened Arduino IDE for ESP32 programming.
  3. Connected the ESP32 to the required Wi-Fi network.
  4. Created and configured the required Adafruit IO dashboard/feed setup.
  5. Added the MQTT communication logic to the ESP32 program.
  6. Connected the ESP32 to the Adafruit IO MQTT service.
  7. Used the dashboard control to send the required value.
  8. Read the received value in the ESP32 program.
  9. Changed the physical output according to the received control value.
  10. Tested both ON and OFF operation.

09

Challenges & Fixes

One important part of troubleshooting was checking the communication path stage by stage instead of assuming that the complete system was working.


  • Cloud communication: Checked whether the Adafruit IO dashboard and feed were communicating correctly.
  • ESP32 connection: Verified whether the ESP32 successfully connected to the network and cloud service.
  • MQTT communication: Checked whether the ESP32 was receiving the expected control information.
  • Physical output: Verified the final output after receiving the command.

Testing each stage separately made it easier to identify whether a problem was related to the dashboard, cloud communication, ESP32 connection or physical output.

10

Reflection

This assignment helped me understand how an IoT device can communicate with a cloud platform instead of operating only locally.


I learned the basic working relationship between an MQTT publisher, subscriber and broker, and understood how a cloud dashboard can be used to control a physical device.


The practical testing also helped me understand that IoT systems need to be checked at every communication stage. A successful dashboard command alone does not guarantee that the physical device will respond correctly.


Overall, this assignment gave me practical experience with ESP32 programming, Adafruit IO, MQTT-based communication and cloud-controlled IoT devices.
